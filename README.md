# 智慧思政 DLC · 给「我的万里 AI 助手」加一套写操作技能

> 浙江万里学院「智慧思政」（`nxg.zwu.edu.cn/zhxg/`）学生端事务的 AI 执行层。
> 装到「我的万里 AI 助手」上之后，学生可以直接说「帮我请个假」「勤工助学的月度反馈填一下」，
> AI 会读数据、生成确认单、等他点「提交」，再替他发出去。

- 版本 **0.6.1** · 契约 `zwu-series/1` · 依赖主程序 **>= 0.2.2**
- 17 个工具（6 个写操作需二次确认 + 4 个草稿 + 7 个只读）
- 59 条离线断言，不碰真账号
- 已实机验证：请假提交（单号 1662814）、课表联动、驳回重提、勤工助学、通用白名单

## 三分钟接入

```powershell
# 1. 把本目录放进主程序的 dlc/ 下
#    主程序目录形如：zwu-ehallapp-assistant-master/

# 2. 安装
cd dlc/xhsz
node install.mjs

# 3. 构建
cd ../..
npm run build
node scripts/prepare-extension.mjs   # 若用浏览器扩展形态
```

然后在浏览器里：

1. `chrome://extensions` → 开发者模式 → 加载已解压的扩展程序 → 选 `chrome-extension/`
2. 打开一次 `https://nxg.zwu.edu.cn/zhxg/#/certificateLogin`（登录智慧思政，token 会同步过来）
3. 回到任意页面，右侧面板就是它

详细步骤与排错见 [INSTALL.md](INSTALL.md)。

## 它能干什么

| 类别 | 能力 | 一句话触发 |
|---|---|---|
| 请假 | 填假条、提交、查进度、销假、返校登记 | 「我明天上午发烧要去医院，帮我请个假」 |
| 请假 | 驳回后改完重提（覆盖原单） | 「我假条被驳回了，单号 1348719，补充说是去复查」 |
| 请假 | 影响面预检（漏哪几节课 + 考勤情况） | 「我明天请假会缺什么课」 |
| 勤工助学 | 月度意见、撤回报名 | 「勤工助学的月度反馈填一下」 |

| 引导 | 11 件多步事务的准确入口（外宿、退宿、调寝、奖助、归寝、手册考试…） | 「外宿怎么申请」 |

完整清单见 **[WORKFLOW.md](WORKFLOW.md)**（8 条工作流的逐句对话脚本）；接口真相与踩坑记录见 **[WRITE-SKILLS.md](WRITE-SKILLS.md)**。

## 安全模型（这是它敢动真实数据的理由）

```
用户说「帮我 X」
   ↓
[draft] 读前置数据 → 生成确认单（做什么、影响什么、能不能撤、下一步一句话）
   ↓ 用户说「提交」
[act]   confirm=true + draft_id → 才真的发请求
```

- 所有写操作**必须** `confirm: true`，缺了直接抛错，一个字节都不发给服务端；
- 草稿 **10 分钟过期、用一次作废**，只有服务端回成功码才标记已用；
- 失败不自动重试；同一张草稿最多试 3 次；
- 通用执行器只收白名单 action + 该 action 声明的字段，**多传一个键直接拒**（防模型乱造字段）。

## 为什么有些事它不代填

智慧思政有 332 条写接口，其中学生端能用的约 30 条。逐条筛完，只有 8 件适合 AI 代填：

- **能代填**：只靠「填值 + 一次 POST」就能完成的（请假、勤工助学…）
- **只能给路径**：多步向导（外宿申请第一步建单拿 `outId`，后面每步都依赖它）、要扫楼栋二维码（归寝）、要家长签字、在别的系统（心理预约在 `xlyy.zwu.edu.cn`）

对后者硬凑接口只会生成必然失败的假单，所以做成「引导卡」：给你准确入口 + 要准备什么 + AI 能帮到哪一步。

## 已知限制

1. 写操作提交需要用户一句话确认（设计如此）。
2. 考勤接口只有学期累计，没有按日期明细。
3. 课表按半天粗分（1-4 上午 / 5-8 下午 / 9+ 晚上）。
4. 油猴版没有 service worker，按节次请假会降级为按天。
5. `exec_command`（本地 bash）在智慧思政页面用不了（跨域拉引擎被拦）。
